Predicting Sales Dashboard

Utilize historical transaction data to predict future sales for an online retail business using XGBoost machine learning regression algorithm

Select a model to view its description and my approach to the problem.

XGBoost builds decision trees sequentially to minimize prediction errors, refining each tree based on the residuals from the previous one—a process known as gradient boosting. This "extreme" version optimizes tree splits by testing various scenarios to improve accuracy, similar to students collectively correcting mistakes for better results. RMSE is used as the loss function for most models, MAPE for Predicted_Sales4 only.

Since the sales models below are meant to predict sales at a transaction level of granularity, I first built a model to predict how many transactions there will be per day solely based on date columns (or features in fancy ML language). This way I can generate a prediction per day amout for any future date without any additional data point, as the future does not have any other information. The settings for this model were chosen using 150 iterations of Bayesian Optimization, smartly mixing testing known good settings (exploitation) with scouting new settings (exploration) using probability theory, choosing the best of settings from all rounds.

In my first model, I mistakenly included exact quantities sold and prices, which directly calculate sales, causing overfitting—it predicted training data well but struggled to generalize. I initially only included Year, Month, and Day from the InvoiceDate, but could have added more features. To capture seasonal trends, I split the data by time order using TimeSeriesSplit with 3 splits, a common choice (3-5). I used RandomizedSearchCV to test 30 different combinations of model settings, like trying on different outfits to find the best fit.

As with the transactions per day model, this second model's settings are chosen with a Bayesian Optimization technique instead as it learns from its mistakes. Unlike the first, I did not include deterministic features like Quantity and UnitPrice. I expanded the features based on InvoiceDate so now the model is trained on Quarters and Season which can help with yearly sales fluctuations. I split the data in a simpler way with 70% trainisng 30% testing. When applying to future data there seem to be less fluctuation in sales as compared to actual, which suggest this model is not very good at estimating days of high or low sales.

The third model adds new features to the training such as: "IsHoliday", which determines if an invoice date is a holiday in a specific country. "Continent" from Country column. "Description" of the item being transacted. Fiscal dates associated from the invoice date. Categorises StockCode's and classifies them according to their length. Given its high performance last time, I stuck with Bayesian Optimization but incremented the number of iterations (how many settings it tests)for the model from 25 to 75. When applying the model to future data, the predictions are smaller than the second but also less dispersed.

Given the third model demonstrated that it is possible to reduce MAPE by a significant amount and given MAPE measures the differences between actual and predicted in relative terms rather than absolute, for the fourth model I decided to use MAPE as a loss function (i.e. minimise it rather than RMSE. In retrospect minimising this measure is more appropriate given sales amount can vary by a lot from transaction to transaction, so having accurate predictions in % or relative terms is more important). I stuck with the same features and same # of iterations of Bayesian Optimization for choosing ideal settings as the third model.

Future 3 month sales predictions

Using the transactions model described above, I apply it to future 3 months of days. Then I randomnly filled combinations of Country, StockCode and CustomerID for each future dates, these are validated so all the combinations are valid (ex. no customer with UK as country appears as having Spain as country in the 3 month future prediction).
